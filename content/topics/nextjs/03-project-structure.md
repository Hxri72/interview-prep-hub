## 💡 What is it?

Next.js gives you a command that **creates a ready project** for you: `create-next-app`.

It makes the folders, installs packages and sets up TypeScript and styling. The most important folder is **`app/`**. Every route (URL) of your site lives there.

Knowing what each file does helps you find your way in any Next.js project.

## 🏠 Real-life example

Think of a **new school building** handed over to the principal.

- The **`app/` folder** = the classrooms. Each classroom has a door number (a URL).
- **`app/layout.tsx`** = the building's walls, roof and main gate. Every classroom is inside it.
- **`app/page.tsx`** = the reception room, the first room you enter (the home page `/`).
- **`public/`** = the notice board in the corridor. Anyone can look at it directly (images, icons).
- **`next.config.ts`** = the building rule book (settings).
- **`package.json`** = the list of supplies and the timetable (packages and scripts).

## 🧑‍💻 Code example

Create the project. You need **Node.js 20.9 or newer**.

```bash
npx create-next-app@latest my-app --yes
cd my-app
npm run dev
```

`--yes` skips the questions and uses the recommended defaults. This is the real folder you get with Next.js 16:

```text
my-app/
├── app/
│   ├── favicon.ico      → the little icon in the browser tab
│   ├── globals.css      → styles for the whole site (Tailwind is imported here)
│   ├── layout.tsx       → the ROOT layout: <html> and <body>, wraps every page
│   └── page.tsx         → the home page at "/"
├── public/              → files served as-is: public/next.svg → /next.svg
├── next.config.ts       → Next.js settings
├── package.json         → packages + scripts (dev, build, start, lint)
├── tsconfig.json        → TypeScript settings (includes the @/* import alias)
├── eslint.config.mjs    → lint rules
├── next-env.d.ts        → generated TypeScript types (don't edit, don't commit)
└── AGENTS.md            → notes that help AI coding tools use the current Next.js APIs
```

Now look at the root layout it created (shortened, with comments added):

**File: `app/layout.tsx`**

```tsx
import type { Metadata } from "next";               // a type for the page title/description object
import "./globals.css";                             // load the global styles once, for every page

export const metadata: Metadata = {                 // SEO info for every page under this layout
  title: "Create Next App",                         // text shown in the browser tab
  description: "Generated by create next app",      // text search engines may show
};                                                  // end of metadata

export default function RootLayout({ children }: LayoutProps<"/">) { // children = the page being shown
  return (                                          // what the layout renders
    <html lang="en">                                {/* the <html> tag is REQUIRED in the root layout */}
      <body>{children}</body>                       {/* the current page is placed inside <body> */}
    </html>                                         // end of the document
  );                                                // end of what RootLayout returns
}                                                   // end of RootLayout
```

```text
npm run dev     → http://localhost:3000 shows the starter home page
npm run build   → makes an optimised production build in the .next folder
npm start       → runs that production build on port 3000
```

**What to notice:** `LayoutProps<"/">` is a **type Next.js generates for you** from your folders. It already knows that this layout gets `children`.

## 🔍 Deeper version

**The setup questions.** Without `--yes`, the CLI asks: TypeScript? Linter (ESLint, Biome or none)? React Compiler? Tailwind? A `src/` folder? App Router? Cache Components? Import alias? AGENTS.md? The recommended answers are yes to TypeScript, ESLint, Tailwind, App Router and Cache Components, and no to `src/` and React Compiler.

**Top-level folders:**

| Folder | Meaning |
|---|---|
| `app/` | App Router routes (the modern way) |
| `pages/` | Pages Router routes (the older way; can exist alongside `app/`) |
| `public/` | Static assets served from `/` |
| `src/` | Optional. If used, `app/` moves to `src/app/` |

**Special top-level files:** `next.config.ts` (settings), `proxy.ts` (code that runs before requests — called `middleware.ts` before v16), `instrumentation.ts` (monitoring), and `.env`, `.env.local` and similar files for [environment variables](topic:nextjs/env-variables).

**Routing files inside `app/`:** `page` (a route's UI), `layout` (shared UI), `loading` (loading UI), `error` (error UI), `not-found` (404 UI), `route` (API endpoint). See [file-based routing](topic:nextjs/file-based-routing) and [special files](topic:nextjs/special-files).

**Organising your own code.** Next.js doesn't force a structure. Common choices are:
- keep shared code in root folders like `components/` and `lib/`,
- or keep it next to the route in **private folders** that start with `_` (like `app/jobs/_components/`). Those are never turned into URLs.

The `@/*` import alias lets you write `import { db } from '@/lib/db'` instead of long `../../` paths.

:::version[Version note]
**Next.js 16** needs **Node.js 20.9+** (Node 18 is no longer supported) and **TypeScript 5.1+**. Turbopack is now the default for both `next dev` and `next build`. Add `--webpack` to use webpack instead. `next lint` was removed, so use ESLint (or Biome) directly. New apps also get an `AGENTS.md` file, so AI coding tools follow the current APIs.
:::

## 🎯 Why do we use it?

- **No setup time.** TypeScript, styling, linting and the bundler work from minute one.
- **One shared layout.** Every Next.js project looks similar, so a new team member finds things quickly.
- **Conventions over config.** File names like `page.tsx` and `layout.tsx` replace router configuration code.

## ⚠️ Common mistakes

- **Deleting `app/layout.tsx` or removing `<html>`/`<body>` from it.** The root layout is required.
- **Putting images in `app/` and expecting `/logo.png` to work.** Static files go in `public/`.
- **Writing `/public/logo.png` in an `src` attribute.** The URL is just `/logo.png`.
- **Committing `.next/` or `next-env.d.ts`.** Both are generated; the default `.gitignore` ignores them.
- **Mixing `src/app` and `app`.** Pick one. If `src/` exists, put `app/` inside it.

## 🗣️ How to answer in an interview

## 🔁 Follow-up questions

### What's the difference between `layout.tsx` and `page.tsx`?

`page.tsx` is the unique content of one route. `layout.tsx` is UI that **wraps** pages (header, sidebar). It **stays on screen** when you move between those pages. See [layouts](topic:nextjs/layouts).

### Can the `app` and `pages` folders exist together?

Yes. This helps teams migrate step by step from the Pages Router to the App Router. A URL must not be defined in both.

### Where do API endpoints go?

In a `route.ts` file inside `app/`, for example `app/api/jobs/route.ts` for `/api/jobs`. See [Route Handlers](topic:nextjs/route-handlers).

### What is `.next`?

The output folder for builds and the dev server cache. It's generated, so don't edit or commit it.

## ✅ Quick check

### 1. You put `logo.png` in the `public/` folder. Which `src` is correct?

- A) `src="/public/logo.png"`
- B) `src="/logo.png"`
- C) `src="public/logo.png"`

:::answer
**B) `/logo.png`.** Files in `public/` are served from the site root, without the word "public".
:::

### 2. Which file must contain the `<html>` and `<body>` tags?

:::answer
**`app/layout.tsx`**, the root layout. It's required in every App Router project.
:::

### 3. Which command runs the production build you made with `npm run build`?

:::answer
**`npm start`** (which runs `next start`). `npm run dev` runs the development server instead.
:::
