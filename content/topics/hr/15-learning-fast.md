## 💡 What they really want to know

Technology changes fast. Companies want people who **learn quickly and safely**.

The interviewer wants:
- a **method** you can repeat, and
- a **real example** that proves it works.

## 🏠 Real-life example

Think of **learning to ride a bicycle**.

You don't read a 300-page book first. You learn the basics — pedal, balance, brake. You try in a quiet lane. Then you ride to school. Then you get better each day.

- **The basics** = the official docs and core ideas.
- **The quiet lane** = a tiny demo project.
- **Riding to school** = using it in real work.
- **Getting better daily** = reviewing and improving.

## 🧩 How to structure your answer

1. **Your method** in one or two lines.
2. **Your real example** — what you had to learn and why.
3. **How you learned it** — docs, demo, then real use.
4. **The result** — what you built.
5. **One lesson** about learning.

## ✅ Do

- Give a **clear method**.
- Use a **real, recent example** — the voice agent is a strong one.
- Name the **specific technologies** you learned.
- Mention **checking AI-generated code** yourself.

## ❌ Don't

- Don't say "I just watch YouTube tutorials."
- Don't claim you learned something "in one day" if it's not true.
- Don't say you copy code from AI without checking it.

Official release notes and docs, small side projects, and using new features at work when they fit.

### How do you use AI tools while learning?

I ask them to explain concepts and draft code. Then I read every line, run it, and check the docs for anything that looks unsure.
